KVH 1775: vehicle configuration for 500 Hz
========================================
The driver reads Format B and expects radians/second and acceleration in g.
It does not issue configuration commands to the IMU. Settings persist in the IMU.
Query the actual settings before changing them. Connect at the current device baud.

At the existing baud (often 921600), enter configuration mode and set:
  =config,1
  =outputfmt,B
  =dr,500
  =rotunits,RAD
  =rotfmt,RATE
  =linfmt,ACCEL
  =filttype,G,BUTTER
  =filttype,A,BUTTER

Confirm replies and query:
  ?outputfmt
  ?dr
  ?rotunits
  ?rotfmt
  ?linfmt
  ?baud

For the vehicle 460800-baud configuration:
  =baud,460800
Then change your terminal to 460800 baud. Confirm communication before sending:
  ?baud
  =config,0
Exit the terminal before starting the driver, so only one process reads the port.

The host driver defaults to 460800 baud, matching the configured vehicle IMU.
A host-only baud change will break reception if the device uses another baud.
KVH's table permits 500 Hz at 460800 and up to 1000 Hz at 921600.

ACCEL always outputs g; LINUNITS only changes delta-velocity units. The driver
converts g to m/s^2. The documented gyro commands are ROTUNITS and ROTFMT.
Butterworth is an IIR filter and is not a linear-phase filter. Filter selection
and bandwidth affect latency and covariance; configure and validate them together.
Keep device AXES at identity when using per-sensor status bits with the ROS frames.

For an FTDI USB connection only, verify the latency setting on the actual adapter:
  echo 1 | sudo tee /sys/bus/usb-serial/devices/ttyUSB0/latency_timer
Use a device-specific udev rule to persist this setting if appropriate. This
setting does not apply to the Jetson's native ttyTHS UART. Do not use zero latency.
